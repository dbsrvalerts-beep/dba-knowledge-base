POSTGRESQL SYSTEMD AUTO-TUNER v4: IMPLEMENTATION STEPS
=======================================================

Deploy pg_autotune_systemd.sh (v4) on your Linux server hosting PostgreSQL 16 or 17.

V4 CHANGES:
  - max_parallel_workers_per_gather local fallback formula updated to: min(4, CPU/2)
  - Email functionality removed entirely (logs write to /u01/backup/logs/autotune/)

---

### STEP 1: Copy the Script to the Server

Upload pgautotune_v4.sh to your server and place it in the /u01/ directory.
Rename it to the canonical name:

    cp pg_autotune_systemd.sh /u01/Gsl/pg_autotune_systemd.sh

---

### STEP 2: Configure User Variables

Open the script and update the USER CONFIGURATION block at the top:

    MAX_CONNECTIONS=5000               # Passed to pgconfig.org API
    WORK_MEM_MB=500                    # Static work_mem (MB)
    WAL_BUFFERS_MB=32                  # Static wal_buffers (MB)
    TEST_SLEEP_SECONDS=30              # Set to 0 in production!

---

### STEP 3: Make the Script Executable

    sudo chmod +x /u01/Gsl/pg_autotune_systemd.sh

---

### STEP 4: Create the Log Directories

The script writes timestamped logs and config backups to /u01/backup/logs/autotune/.
Create the necessary directories now:

    sudo mkdir -p /u01/backup/logs/autotune/config_backup

---

### STEP 5: Fix SELinux Context (CRITICAL — Do NOT skip)

**What:** SELinux assigns a generic data label to files in /u01/.
Systemd refuses to execute files without the official 'bin_t' binary label.

**Command:**

    sudo chcon -t bin_t /u01/Gsl/pg_autotune_systemd.sh

**Verify:**

    ls -Z /u01/pg_autotune_systemd.sh
    # Should show: system_u:object_r:bin_t:s0

Skipping this step causes "Permission denied" errors during ExecStartPre execution,
even if chmod +x is set correctly.

---

### STEP 6: Add the Hook to the Systemd Service

Open the main PostgreSQL systemd service file directly using a text editor (like vi):

    sudo vi /usr/lib/systemd/system/postgresql-16.service   # or postgresql-17.service

Find the `[Service]` block and insert this line right below it:

    ExecStartPre=+/u01/Gsl/pg_autotune_systemd.sh

IMPORTANT: The '+' prefix is mandatory. It grants the script root execution privilege.
Without '+', the script runs as the postgresql service user and will fail.

Save and close the file.

---

### STEP 7: Apply the Changes

    sudo systemctl daemon-reload

---

### STEP 8: Test the Integration

Stop and start PostgreSQL to trigger the hook:

    sudo systemctl stop postgresql-16
    sudo systemctl start postgresql-16

During startup, open a second terminal and watch the status.
If TEST_SLEEP_SECONDS=30, you will see the service pause for 30 seconds:

    systemctl status postgresql-16

After startup completes, check the log:

    cat /u01/backup/logs/autotune/pg_autotune_*.log

You should see the tuning trace including:
  - Hardware detection output
  - "HARDWARE CHANGE DETECTED" block (first run always triggers)
  - Before → After trace for each of the 8 parameters
  - "Process complete. State saved inside script."

---

### STEP 9: Go to Production

After successful validation, disable the test sleep:
Edit the script and set:

    TEST_SLEEP_SECONDS=0

Then reload:

    sudo systemctl daemon-reload

---

### V4 MEMORY & CPU FORMULA REFERENCE

The following parameters are auto-calculated from /proc/meminfo MemTotal:

  Parameter              Formula                          Example (64 GB RAM, 16 CPUs)
  ---------------------  -------------------------------  ----------------------------
  shared_buffers         RAM_MB * 26 / 100               17039 MB  (~16.6 GB)
  effective_cache_size   RAM_MB * 76 / 100               49807 MB  (~48.6 GB)
  maintenance_work_mem   max(RAM_GB / 20, 1) * 1024 MB   3072  MB  (3 GB)
  work_mem               Static: WORK_MEM_MB             500   MB
  wal_buffers            Static: WAL_BUFFERS_MB          32    MB

CPU/Parallel parameters come from pgconfig.org API. 
If the API fails, the local fallback math applies:

  max_worker_processes            CPU_CORES                      16
  max_parallel_workers            CPU_CORES                      16
  max_parallel_workers_per_gather min(4, CPU_CORES / 2)          4

### TROUBLESHOOTING

Problem: PostgreSQL fails to start after hook is added
Fix:     Run: sudo chcon -t bin_t /u01/pg_autotune_systemd.sh
         Verify: ls -Z /u01/pg_autotune_systemd.sh (look for bin_t)

Problem: No log file in /u01/backup/logs/autotune/
Fix:     Run: sudo mkdir -p /u01/backup/logs/autotune/config_backup
         Also check: journalctl -xe for systemd-level errors

Problem: Script runs but no tuning happens (no parameter changes)
Fix:     LAST_KNOWN_STATE inside the script may already match.
         Edit the script and set: LAST_KNOWN_STATE="First Run"
         Save and restart the service.

Problem: API fallback math used every time
Fix:     Normal if server has no outbound internet access. Fallback is intentional.
